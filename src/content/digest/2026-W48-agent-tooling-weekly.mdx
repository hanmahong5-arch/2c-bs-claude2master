## 本周看点
本周 agent 工具链的主基调是「把执行关进笼子」：从 Simon Willison 提出的 external sandbox 模式，到 Codex、Claude Code、gemini-cli、opencode 集中修复沙箱权限、凭据竞态与审批边界，隔离与权限正从附加项变成架构前提。与此同时，模型侧 GPT-6.2 Astra/Sol、Gemini 4 Neon 密集发布，成本与 harness 适配成为选型关键变量。

## 本周实测
挑 opencode v2.3.2 的提示词缓存修复来复现：在 c2m 本地装好 opencode 后，用 GitHub Copilot 路由的 `gpt-6.2-sol` 跑一个多步任务（例如让它读三个文件并改一处代码），在请求日志里记录每步的未缓存输入 token 数。升级到 v2.3.2 后重跑同一任务，预期看到系统提示词不再作为 `instructions` 字段重复计费，单步未缓存输入从约 14,000 token 降到个位数，总费用相应下降。可对照 release 说明 [链接](https://github.com/anomalyco/opencode/releases/tag/v2.3.2) 确认缓存前缀行为。

本周最明显的贯穿性设计观察是「隔离边界从整机收缩到执行层，并成为可配置的一等公民」。证据有三：Simon Willison 的 external sandbox 把 agent 本体留在沙箱外、只让执行代码进入沙箱，并内置 HTTP allow-list 与凭据替换（[链接](https://simonwillison.net/2026/Nov/17/external-sandboxes-for-coding-agents/)）；Codex v0.170.0 把权限视为会话级不变量，子线程不再丢失既有沙箱限制（[链接](https://github.com/openai/codex/releases/tag/rust-v0.170.0)）；gemini-cli v0.70.0 让含未解析展开的 shell 命令保持 ASK_USER，审批基于解析后的真实命令（[链接](https://github.com/google-gemini/gemini-cli/releases/tag/v0.70.0)）。对 harness 设计者的含义是：权限、网络出口与凭据管理不能再散落在各工具实现里，而应作为执行环境的统一配置项，且默认拒绝、可审计。

## 编辑没选它的原因
本周刻意没展开两类 release：一是 codex rust-v0.169.1，发布说明明确无实质变更、仅版本对齐，展开没有信息增量；二是 Gemini 4 Neon 官方发布公告与 Daybreak Blue 入门演示，前者正文缺失无法核实能力，后者只是 onboarding 视频，均不适合作为本周主线。此外 openclaw v2026.10.33 属 extended-stable 分支的维护性修复，与本周主线（沙箱与权限）关联较弱，仅作速览保留。
