## 本周实测
挑 claude-code v2.1.314 的写入边界做本地复现：在项目根目录建 `outside/` 与 `src/`，启动 `claude` 后要求它把 `src/a.txt` 内容写入 `../outside/b.txt`。预期看到 Write 工具被 `permissions.blockWritesOutsideWorkingDirectories` 直接拒绝，即使切到 bypass 模式也不放行；再让它写 `src/b.txt` 应成功。随后在 `.claude/settings.json` 里把该开关设为 false 重跑，对比行为差异，即可确认这是工具级恒定约束而非提示词约束。

## 设计趋势
本周最清晰的贯穿线是「权限与状态从模型自觉下沉为运行时契约」。证据有三：claude-code v2.1.312 要求写超大文件前先读全文，v2.1.314 又把工作目录外写入做成所有权限模式下都拒绝的恒定约束；codex v0.166.0 在 resume/fork 时保留已确认的审批与 reasoning token 计数，把权限与账本变成可持久化会话状态；opencode v2.2.0 把动态指令做成增量条目而非重写系统提示，避免缓存失效。对 harness 设计者的含义是：边界要写在工具与调度层，且状态要能跨恢复存活，不能指望模型每轮重新遵守。
