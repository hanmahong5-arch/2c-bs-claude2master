## 本周看点
本周 agent 工具链的主基调是“边界收紧”：决策模型（Decision Models）开始形成统一接口，而 harness 侧则集中修复权限、凭证、子代理生命周期等边界问题。从 openclaw 的隐私修复到 claude-code 的沙箱默认收紧，再到 goose 的子代理续跑，控制面正在变厚。

## 本周实测
以 **openclaw v2026.11.3** 为例，在 c2m 本地复现子任务隐私修复：1) 启动 openclaw 网关并配置一个父任务，父任务内创建一个私有子任务；2) 在子任务中执行一个返回敏感数据的工具调用（如读取本地文件）；3) 观察父任务的流式聊天回复。预期看到：子任务的完成结果不会出现在父任务的流式输出中，父任务只收到内部完成回执；若父任务取消子任务，交接仍能正常进行。可参考 release 说明中的测试用例，用 `openclaw test --scenario private-subtask` 运行。

本周最明显的设计趋势是 **harness 控制面变厚**，具体证据有三：1) **goose v1.59.0** 引入子代理续跑、工具钩子拦截和延迟 MCP 工具，把子代理生命周期和工具执行策略纳入 harness 管理；2) **claude-code v2.1.325** 将沙箱 Bash 默认改为走正常权限流程，要求显式授权才免提示，并把信任与沙箱权限解耦；3) **zeroclaw v0.9.0** 要求逐请求校验权限，无法归属的调用默认拒绝。这些改动共同指向一个含义：agent harness 不能再假设“沙箱即安全”或“登录即授权”，而必须把权限、凭证、子代理状态作为一等公民显式管理。对 harness 设计者而言，控制面需要支持可重入的清理与恢复、按调用者身份裁剪工具面、以及会话级与默认配置的分离存储。
