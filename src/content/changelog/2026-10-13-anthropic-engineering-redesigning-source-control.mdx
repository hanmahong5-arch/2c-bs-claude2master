- 客户端永远在线：Scion 假设 agent 与任务始终可连服务端，按需拉取数据，而非像 git 那样要求完整离线副本。对 harness 的含义：可以放心把状态与历史放在远端，本地只保留有界缓存。
- 客户端-服务端不对称：服务端负责历史、blame、commit、merge/rebase，客户端只做缓存、工作区布局与文件监控。对 prompt/工具设计的含义：把重计算与全局查询收敛到服务端 API，工具调用更轻。
- 工作副本可选且稀疏：CI 可直接向服务端要 diff 或 merge base，写操作也能纯 API 完成，虚拟化 checkout 按需物化文件。对 harness 的含义：能省掉 checkout 就省掉，减少 agent 沙箱的 I/O 与准备成本。
