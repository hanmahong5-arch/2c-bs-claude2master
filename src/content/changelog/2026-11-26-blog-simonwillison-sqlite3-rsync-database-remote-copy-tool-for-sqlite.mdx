- 传统快照要靠 backup API 或 VACUUM INTO，必须先在本机复制一份完整数据库；磁盘占用过半的小实例就做不了。sqlite3_rsync 则通过 SSH 把快照直接传到另一台机器，不需要本地全量副本——对资源受限的 agent 部署环境是实用的备份路径。
- 同步已有副本时，它不会重传整个数据库：副本把页或页组的加密哈希发给源端，源端只回传有差异的页，必要时再请求更细粒度的哈希。增量同步因此省下大量带宽。
- 两端差异极大时，交换哈希的开销会让总带宽略超数据库本身大小，但超出幅度很小，最多几个百分点。这意味着工具链里可以放心把它当作常规同步手段，不必担心极端情况下的带宽爆炸。
