- **Channel docking 实现会话转发**：从一个聊天应用（如 Telegram）发送 `/dock_discord` 命令，后续回复会转到 Discord，而对话历史不变。这意味着 agent harness 需要支持动态修改会话的投递目标，且不重建会话。
- **依赖 identityLinks 配置**：必须将源发送者和目标对等体放在同一身份组中，例如 `alice: ["telegram:123", "discord:456"]`。这要求 prompt 设计时明确用户身份映射，确保跨平台绑定。
- **仅改变投递路由**：docking 不创建新会话、不迁移历史、不绕过权限策略。这提示 agent harness 应保持会话状态稳定，只更新 `lastChannel` 等字段，避免副作用。
