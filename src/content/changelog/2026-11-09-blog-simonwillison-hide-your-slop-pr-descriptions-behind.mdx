- 作者现在多数 PR 由 Claude Code 或 Codex 提交，agent 写的描述准确全面，但读起来像 slop，他的第一反应是「我不看这么多」。含义：agent 输出越长不等于越有用，信息密度和可扫读性才是评审成本的关键。
- 他的做法是在 GitHub Markdown 里用 `<details><summary>` 折叠 agent 写的完整说明，summary 直接写模型名和 effort 级别（如 Claude Opus 5.5 Medium），开头只留一段人工挑选的高层介绍，必要时配截图。含义：工具链可以把「人审摘要」和「机器详述」分层呈现，让评审者先看结论。
- 他承诺开头那段代表自己的人类判断，并给出 datasette、datasette-agent、llm 等多个 PR 实例，还建议 GitHub 在 Markdown 编辑器加按钮。含义：agent 工作流需要为人类编辑判断留出显式位置，而不是让模型包办全部叙述。
