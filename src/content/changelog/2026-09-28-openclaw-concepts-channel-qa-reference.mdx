- 各频道 QA 共用一套 CLI 契约：`--scenario`、`--output-dir`、`--provider-mode`、`--credential-source` 等标志统一注册，QA Lab 作为套件宿主。含义：harness 设计应把传输插件与套件宿主解耦，用统一参数面降低新增频道的接入成本。
- Buzz 默认用 `mock-openai` 提供者，只验证真实 Nostr 中继传输，不依赖模型凭据；Telegram 固定 `--credential-source convex`，用 Test Server 的独立 TDLib 授权跑真实群组。含义：prompt/harness 应把“传输正确性”与“模型行为”分层验证，避免凭据耦合掩盖传输缺陷。
- 每次运行输出 `qa-suite-report.md`、`qa-suite-summary.json`、`qa-evidence.json`，报告记录真实中继路径但省略凭据值；失败场景默认非零退出，`--allow-failures` 仅写产物。含义：agent 评测的产物应结构化、可审计，且默认失败即失败，防止静默通过。
