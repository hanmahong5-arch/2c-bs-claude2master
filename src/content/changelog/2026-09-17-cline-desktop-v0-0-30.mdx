- **Windows 更新不再报 "Error opening file for writing"**：旧安装器用 32 位 NSIS，PowerShell 跑在 WOW64 下 `Get-Process` 拿不到 64 位进程路径，过滤永远匹配不到 sidecar，于是覆盖了仍被 Hub 守护进程占用的可执行文件。现改用 Windows Restart Manager 按文件占用关进程，与位数无关，且不影响并存的 Cline Beta。含义：harness 的安装/升级路径要按“谁持有文件”而非按进程名判断。
- **不再从工作区执行同名程序**：Windows 先按子进程工作目录解析裸程序名再查 PATH，而 Cline 以工作区为 cwd 运行 `rg`、`git`、`powershell`，仓库里放个 `rg.exe` 就会被执行。现启动时禁用当前目录可执行搜索，所有子进程继承。含义：agent 的 shell 执行层必须显式关闭 cwd 优先解析。
- **长会话压缩触发改用 provider 上报的 token 数**：原先按 ~3 字符/token 估算，反汇编、图片、压缩源码等密集内容会撑爆真实上下文而估算仍低于阈值，压缩不触发，回合被压到只剩几个输出 token。现同时参考真实 token 数，保留历史量按估算偏差缩放，摘要器输出预算翻倍。含义：上下文管理不能只靠字符估算。
