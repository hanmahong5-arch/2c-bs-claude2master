- 插件从子进程改为每进程一个注册表在进程内加载，编译后的 CLI 与 hub 不再依赖 PATH 上的运行时；`CLINE_PLUGIN_MODE=sandbox` 仍保留子进程沙箱。含义：harness 需为插件加载、setup、hooks、tools、commands 统一加超时与错误捕获，并跟踪 loading/ready/degraded/failed/disabled 状态。
- 插件失败不再静默丢弃其工具：`session.create` 接受 `plugins` 策略并返回 `pluginIssues`，后续失败以状态通知进入受影响会话，hub 提供 `plugins.list`/`status`/`reload` 并广播 `plugin.status_changed`。含义：插件故障要作为可观测状态面暴露给会话，而非吞掉能力。
- 每个会话获得每个插件模块的独立副本，模块级保存的会话状态仍可用；daemon 在未捕获错误来自某插件时将其标记为 failed 而非整体退出。含义：隔离粒度决定插件能否安全持有会话态，崩溃边界应落在插件而非进程。
