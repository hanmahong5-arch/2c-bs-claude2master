- 修复点：用 `add_database(db, name=..., route=...)` 注册数据库时，若 route 与 name 不同，被拒绝访问的 actor 仍可通过 `/<route>.db` 下载整库。含义：权限校验必须绑定实际暴露的 URL 路径，而不是逻辑名。
- 该修复从 1.0a43 回填到 0.65.6 维护分支。含义：稳定版用户不必升级到 alpha 才能拿到安全补丁，维护分支的 backport 流程值得在工具链里常态化。
- 触发条件是 route 与 name 不一致这一非默认配置。含义：给 agent 或自动化脚本封装数据库注册接口时，应避免让两个标识符各自独立可寻址，减少权限面。
