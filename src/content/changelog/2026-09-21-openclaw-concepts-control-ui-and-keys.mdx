- 密钥写入与目录刷新解耦：保存 key 和刷新 catalog 是两个独立结果，刷新失败时已保存的 key 仍然保留，只需按提示执行恢复步骤。对 harness 的启示是凭证写入与状态同步应各自独立，避免一次失败回滚全部操作。
- 密钥轮换只在限流时触发：按 OPENCLAW_LIVE_<PROVIDER>_KEY、<PROVIDER>_API_KEYS、<PROVIDER>_API_KEY、编号列表的优先级选 key 并去重，仅对 429、quota、ThrottlingException 等限流响应换下一个 key，非限流错误立即失败。含义是重试策略应按错误分类，而非无差别重试。
- Provider 逻辑下沉到插件：registerProvider(...) 承担 onboarding、模型目录、环境变量映射、工具 schema 清理、故障分类、OAuth 刷新等，核心只保留通用推理循环。对 prompt/harness 设计的含义是 provider 差异应通过显式钩子暴露，而非共享逻辑里的静态能力标记。
