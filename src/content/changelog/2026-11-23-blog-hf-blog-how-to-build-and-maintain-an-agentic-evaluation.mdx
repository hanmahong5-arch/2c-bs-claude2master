- 文章把 agent 评测当成需要持续维护的工程，而不是一次性跑分：评测集要随模型与工具变化更新，否则分数会失真。对开发者的含义是，评测要像代码一样纳入版本管理。
- 文中强调 agent 评测要覆盖多步任务与工具调用过程，而非只看最终答案。这意味着工具链需要记录中间步骤，才能定位失败环节。
- 作者建议用可复现的环境与明确的评分标准来降低评测噪声。对 agent 团队来说，先固定环境再谈提升分数，否则对比没有意义。
